    01

    网站到底是什么

    先说结论：一个网站，就是一堆文件，放在一台永远开机的电脑上，别人通过浏览器来取。

    你可以把它想成开一家餐厅。餐厅需要三个条件：有店面（文件），有地址（网址），有人帮你守着店、把菜端出去（托管服务器）。客人不用知道厨房长什么样，他只要推门进来点菜就行。

    生活类比

    你现在双击打开一个 Word 文档，看到的是内容。网站也一样：浏览器打开一个网页，本质上是从远方那台电脑上取回一个文件，然后把它画出来。

    如果你写过 C 语言，那更好理解：

    C 语言类比
    • index.html 就像 main.c，是整个程序的入口，浏览器默认先找它。
    • 标签成对出现 就像 { } 括号，开一个就必须关一个，少一个就会出错。
    • 浏览器 就像编译器加运行环境，它读懂你的文件，然后把画面"运行"出来。
    • 区别在于：C 写错会编译不过，网页写错通常不报错，只是画面变丑或者某块不显示。所以网页更能"边做边看"。

    记住这一句就够开工了：网页是文件，网站是文件夹，上线就是把文件夹搬到一台公开的电脑上。文件夹和文件怎么分图标是黄色夹子的叫文件夹，里面可以装东西；图标是一张白纸的才叫文件。改完名之后看窗口里「类型」那一列最准。

    很多教程一上来就讲服务器、数据库、框架，把人吓跑了。你先别管那些，做静态网站只要三样。先别花钱不用一上来买服务器、买域名、装 Linux。等网站跑起来、真有人看了再说：先做出来，再做好，最后才做贵。

    一个文件夹

    里面放你的网页文件。命名用英文小写，别用空格，比如 my-site。

    一个入口文件

    必须叫 index.html。这是默认首页，名字错了就是一片空白。

    一个托管平台

    免费的就够用。它负责把你的文件挂在网上，给你一个链接。

    03

    写出你的第一个网页

    新建一个文件夹，在里面新建一个后缀为 .html 的纯文本文件，名字叫 index.html怎么确认建对了改完名字看「类型」列：显示 HTML 文档才对；显示「文件夹」说明你把夹子建出来了，删掉重来。实在不确定就右键 → 属性，看文件类型。。

    别把"文本文件"想得很玄。它就是你在记事本里敲的那几个字，没有任何特殊格式。真正决定它身份的，是后缀名：后缀是 .html，浏览器把它画成网页；后缀是 .txt，浏览器只会把代码原样吐给你看。

    先避开这个坑

    Windows 默认隐藏已知文件类型的扩展名。你新建"文本文档"再改名成 index.html，系统很可能偷偷把它存成了 index.html.txt，你看着一模一样，打开却是一堆代码。

    两个办法确认：在文件夹顶部点「查看」→ 勾选「文件扩展名」，看清真实后缀再改名；或者右键文件 → 属性，确认"文件类型"写的是 HTML 文档，不是文本文档。

    确认后缀没错之后，用记事本或 VS Code 打开它，把下面这段原样抄进去，保存。

    index.html 
    <!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一个网站</title>
</head>
<body>
  <h1>你好，世界</h1>
  <p>这是我做的第一个网页。</p>
</body>
</html>

    保存后，双击这个文件，它会在浏览器里打开。看到"你好，世界"这几个大字，说明你已经成功了一半。

    不想一个字一个字抄？

    这份说明书配套的示例文件已经打包好了，下载解压，直接在上面改。

    下载 starter.zip

    这几行分别是什么意思

    你看到的它干的事类比
    <!DOCTYPE html>告诉浏览器这是网页，不是别的文件文件开头声明版本
    <head>放给浏览器看的信息，不显示在页面里程序的配置区
    <meta charset>声明用 UTF-8，中文才不会乱码指定字符编码
    <title>浏览器标签页上的名字程序的名字
    <body>所有能看见的内容都放这里main 函数体
    <h1> / <p>大标题 / 段落printf 输出不同格式

    再把这两行拆开看

    示例里 body 中其实只有两行内容，一行标题、一行段落少一个斜杠会怎样标签必须成对。只写 <h1> 忘了 </h1>，浏览器会以为标题还没结束，把后面所有内容都当成大标题。<p> 同理。：

    body 里真正显示出来的两行 
    <h1>你好，世界</h1>
<p>这是我做的第一个网页。</p>
    这一行拆开来看
    <h1>开场标签，h1 意思是"一号标题"，里面的字会自动变大变粗
    你好，世界你真正想让访客看到的文字，写什么都行
    </h1>收尾标签，多了一个斜杠，表示"标题到此结束"
    <p>p 是 paragraph 的缩写，表示"一段话"，不是标题
    这是我做的第一个网页。段落里的文字，浏览器会自动在段落前后留出空隙
    </p>段落结束，后面的内容就不再算这一段了

    第一行里的 h1，那个 1h1 的 1 是级别，不是字号h 是 heading（标题）的缩写，1 表示第一级：最重要，字也最大。网页一共六级，从 h1 到 h6，数字越大级别越低、字越小。

    • h1：整页的主标题，一页只写一个
    • h2：文章里的小节标题
    • h3：小节下面再分一层
    浏览器默认就会把 h1 放大加粗，所以不用自己调字号；也别为了字大，把正文硬写成 h1。级别到 h6 为止，没有 h7。不是"字号一号"，而是"标题的级别是一级"。

    生活类比

    标签像快递箱上的"易碎品"贴纸，箱子里的东西才是商品。贴纸只负责告诉快递员怎么搬，不会落到你手上。浏览器也一样，它只认标签，但不会把尖括号画到页面上。

    head 像房子的水电管道，埋在墙里你看不见；body 像客厅，所有家具和摆设在明面上。装修时你只关心客厅，但水电没做好，灯就不亮。

    想加更多内容，就继续加标签

    在 body 里面一行一行往下加就行，顺序就是从上到下的显示顺序。

    body 里的常见标签 
    <h1>网站大标题</h1>
<h2>一节的小标题</h2>
<p>一段正文，写什么都行。</p>
<img src="photo.jpg" alt="一张照片">
<a href="https://example.com">点我去另一个网站</a>
<ul>
  <li>列表第一项</li>
  <li>列表第二项</li>
</ul>
<button>点我</button>

    图片要放在同一个文件夹里，文件名和 src 里写的一模一样，大小写也要一致。

    04

    给页面化妆：CSS

    HTML 负责"有什么"，CSS 负责"长什么样"。同一个内容，换个 CSS 就是完全不同的气质。

    新建一个文件叫 styles.css（不是文件夹，建法和 index.html 一样），和 index.html 放在同一个文件夹里。然后在 HTML 的 head 里加一行，把它引进来——位置是 <head> 和 </head> 之间，不是 body 里。两个文件，各放各的

    • CSS 规则整段粘进 styles.css
    • index.html 只加一行 link，放在 head 里
    千万别把 CSS 粘进 body，那样会变成页面上的文字。

    在 head 里加这一行 
    <link rel="stylesheet" href="styles.css">

    然后往 styles.css 里写规则。每条规则都是"选谁 + 改成什么样"：

    styles.css 
    body {
  font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
  background: #fbf9f5;
  color: #222;
  max-width: 720px;
  margin: 0 auto;
  padding: 40px 20px;
  line-height: 1.8;
}

h1 {
  color: #3b3bd1;
  font-size: 40px;
}

button {
  background: #3b3bd1;
  color: #fff;
  border: none;
  border-radius: 8px;
  padding: 10px 20px;
  font-size: 16px;
}
    C 语言类比

    CSS 有点像 #define 加全局配置：你在一处写好"按钮是蓝色的"，所有按钮都自动变蓝。改一次，处处生效。这就是它比一个个标签手写样式更省力的原因。

    生活类比

    HTML 是毛坯房，CSS 是刷墙、铺地板、换灯具。房子结构没变，但住起来的感觉全变了。而且装修可以随时改，不用拆房子。

    最常用的几条属性

    属性作用怎么记
    color文字颜色color 就是颜色
    background背景色或背景图背景
    font-size字号font 是字体
    margin外边距，元素外面的空隙外面的距离
    padding内边距，元素里面的空隙里面的肉
    border-radius圆角radius 是半径
    05

    让按钮真正动起来：JS

    HTML 是骨架，CSS 是皮肤，JavaScript 是神经。它让页面能对点击、输入、滚动做出反应。

    先分清文件还是文件夹

    script.js 是文件，不是文件夹。建法和 index.html 完全一样：右键 → 新建 → 文本文档 → 把整个名字改成 script.js，改完看一眼"类型"列，显示的是 JS 文件而不是"文件夹"，才算对。建完应该有三样东西同一个文件夹里并排放着：index.html、styles.css、script.js。三个都是纸片图标；如果哪个是夹子图标，就是建错了。

    这三行加在 index.html 的哪个位置

    不需要新建 body。页面只有一个 <body>，你要做的是在它里面、</body> 的上一行，加上这三行。

    index.html · 完整样子（彩色三行是新增的） 
    <!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一个网站</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <h1>你好，世界</h1>
  <p>这是我做的第一个网页。</p>

  <p id="msg">现在还没有人点我。</p>  <button id="btn">点我一下</button>  <script src="script.js"></script>
</body>
</html>
    编号加在哪一行之后加什么
    ①<p>这是我做的第一个网页。</p> 的下一行<p id="msg">现在还没有人点我。</p>
    ②① 的下一行<button id="btn">点我一下</button>
    ③紧贴 </body> 的上面一行<script src="script.js"></script>

    顺序别调：script 必须放在按钮后面，否则 JS 执行时页面上还没有按钮，它就会报"找不到元素"。整段粘贴到文件里时，编号 ①②③ 不要抄进去。

    再新建 script.js，写上这几行：

    script.js 
    const btn = document.getElementById("btn");
const msg = document.getElementById("msg");
let count = 0;

btn.addEventListener("click", function () {
  count = count + 1;
  msg.textContent = "你已经点了 " + count + " 次。";
});
    C 语言类比

    getElementById 像拿到一个变量的地址；addEventListener 像注册一个回调函数；count = count + 1 就是你熟悉的 count++。区别是 C 里你手动调用，这里由"点击"这个事件替你调用。

    生活类比

    网页原本是一张海报，只能看。加了 JS，海报变成了电梯：你按一下，它才有反应。开关装在墙上，但真正让灯亮的是里面的电路。

    新手最常见的问题

    JS 写在 body 最底部，或者给 script 加 defer。如果写在前面，代码执行时按钮还不存在，就会报"找不到元素"。

    06

    加图片，再加第二个页面

    只有一个页面的网站，像一张名片；加上图片和第二个页面，才像一个真正的站。

    先记住一个前提：图片也是文件，必须和网页放在一起。网页里写的不是图片本身，而是"去哪个文件夹、找哪张图"，这行说明就叫路径。不能把图片拖进网页里拖进去只是临时显示，文件一保存就没了。正确做法是把图片复制进文件夹，再用 <img> 指过去。

    第一步：建一个 images 文件夹

    在 index.html 旁边右键 → 新建 → 文件夹，名字改成 images，全小写，别用中文和空格。然后把你的图片复制进去。

    第二步：用 img 标签把图放进去

    在 body 里想显示图片的位置，加这一行。文件名换成你自己的：

    index.html 
    <img src="images/photo.svg" alt="一张示例插画">

    src 是"图片在哪"，alt 是"图片没出来时显示的文字"，读屏软件也会念它。alt 不要留空，用一句话说清图里是什么。

    裂图，八成是这三个原因
    • 大小写不一致：Photo.jpg 和 photo.jpg 是两个文件。服务器认大小写，Windows 不认，所以本地好好的，上传就裂。
    • 文件名带中文或空格：改成英文小写，用短横线分隔，比如 my-photo.jpg。
    • 写了本地绝对路径：C:\Users\... 只在你电脑上有效，上线一定裂。改成 images/photo.svg。
    C 语言类比

    src="images/photo.svg" 就像 #include "images/photo.h"：相对当前文件去找，搬到哪里都能用。写成 C:\Users\... 就像写死了本机的绝对路径，换台电脑就找不到。

    生活类比

    img 是墙上的相框，src 是相框背后那张便签，写着"照片在第二个抽屉"。抽屉一换位置，相框里就只剩 alt 那行字。所以路径要对，位置别乱挪。

    第三步：做第二个页面

    把 index.html 复制一份，改名 about.html（还是同一层文件夹里）。打开它，把 title 和 body 里的字改掉，比如改成"关于我"。结构不用动，CSS 和 JS 的引用也照旧。

    然后用 <a> 把两个页面互相连起来。href 写的是目标文件名，不是网址：

    两个页面各加一个链接 
    index.html 里：
<a href="about.html">关于我</a>

about.html 里：
<a href="index.html">回到首页</a>

    存盘后双击 index.html，点"关于我"能跳过去，再点"回到首页"能跳回来，就成功了。跳不过去，先检查两个文件名有没有拼错、是不是在同一个文件夹里。

    生活类比

    两个页面像两间房，a 标签就是门。门牌写错了，客人就敲到别人家；没有门，客人只能待在原地。现在你的房子有两间，可以互相串门了。

    07

    先在本机试营业

    改一句、存一下、刷新浏览器，这是网页开发最舒服的地方：改完立刻能看到结果。

    最省事的办法：双击 index.html，浏览器直接打开。缺点是地址栏显示的是本地文件路径，而且有些需要"服务器环境"的功能跑不了。日常做静态页面，这样完全够用。

    想更接近真实环境，可以在文件夹里开一个本地小服务器。装好 Node.js 之后，在这个文件夹打开终端，运行：

    终端 
    npx serve .

    它会给你一个 http://localhost:3000 这样的地址，在浏览器里打开就是你的网站。

    C 语言类比

    双击打开像是直接运行 a.exe；npx serve 像是先在本地起一个调试环境再运行。前者快，后者更接近正式上线后的样子。

    生活类比

    这就是正式开业前的试营业。先请家人朋友来吃一顿，看看菜咸不咸、椅子稳不稳。等自己满意了，再挂招牌对外营业。

    08

    把文件传上网

    先选平台，再动手。平台选错了，后面每一步都别扭；选对了，第一次上线只要点几下。

    免费的静态托管就这几家，差别主要在"国内打开快不快"和"要不要实名备案"：

    平台国内速度门槛怎么传适合谁
    Netlify
    推荐    		一般一个邮箱就能注册把文件夹拖进网页第一次上线，想最快看到结果
    Vercel一般邮箱注册，有时要验证手机拖拽或连接仓库以后可能写前端项目的人
    GitHub Pages偏慢要有 GitHub 账号上传到仓库，不能直接拖文件夹愿意顺便学 Git 的人
    阿里云 OSS / 腾讯云 COS快要实名，绑自己域名要备案控制台里逐个上传主要给国内用户看、打算买域名的人
    Netlify 拖拽上传 Vercel 新建项目 GitHub 注册 GitHub Pages 说明 阿里云 OSS 腾讯云 COS

    下面用 Netlify 走一遍，因为它的拖拽最直观。其他平台的按钮名字不一样，动作是一回事：注册 → 找到上传入口 → 把文件夹拖进去 → 等网址。

    1. 注册登录：打开 app.netlify.com，用邮箱注册，或者直接用 GitHub 账号登录。
    2. 找到上传入口：进入 Sites 页面，点 Add new site → Deploy manually。找不到就记住这个专用地址：app.netlify.com/drop。
    3. 拖文件夹：页面中间会出现一个虚线框，把整个 my-site 文件夹拖进去。注意拖的是文件夹本身，不是把里面的文件一个个拖。
    4. 等它变出网址：十几秒到半分钟，页面会给一个 https://xxx.netlify.app 的链接。点开能看到你的首页，就成功了。
    5. （可选）换个好记的名字：Site configuration → Change site name，改成你的名字，网址就跟着变。界面是英文的，还会改版不用逐字对。找 Add new site、Deploy manually、drag and drop 这几个词，意思都是"新建站点、手动部署、把文件拖进来"。按钮位置变了也照样找得到。

    如果选了 GitHub Pages

    步骤多一点，但完全免费、能一直用：注册 GitHub → 新建一个仓库（选 Public）→ Add file → Upload files，把 index.html、styles.css、script.js、about.html 和 images 文件夹都传上去 → 进仓库的 Settings → Pages → Source 选 main 和 / (root) → 保存 → 等一两分钟，得到 https://你的用户名.github.io/仓库名/。

    传完打不开，先查这两条
    • 打开是 404 或一串文件列表：文件夹多套了一层。网站根目录里必须直接看到 index.html；如果看到的是 my-site/index.html，就重新上传 my-site 里面的内容。
    • 本地正常，线上裂图：文件名大小写或中文名的问题，回到第 6 节核一遍。
    生活类比

    托管平台就像商场里的共享铺位：你把自己的货摆进去，商场负责开门、供电、指路。你不需要自己盖楼，也不用24小时守着。货卖得好，再考虑租个独立门面。

    09

    门牌号和上锁：域名与 HTTPS

    平台给的网址能用，但不好记。域名就是给你的店换一块好记的招牌。

    域名需要按年购买，买完要"解析"到平台给你的地址上。解析的动作，说白了就是填一张表：告诉全世界"访问我这个名字，请去那台机器"。

    C 语言类比

    域名像宏定义或别名：#define MY_SITE 123.45.67.89。用户只记名字，系统自动替换成真实地址。域名解析服务器就是那张对照表。

    HTTPS 是地址栏里那个小锁。它让浏览器和网站之间的传输被加密。现在主流平台默认就带，不用你手动配置。如果没有，说明你还在用很老的方案，换一个平台就好。

    生活类比

    HTTP 像寄明信片，路上谁都能看；HTTPS 像寄挂号密封信，只有收件人能拆。区别就这么大。

    别急着买

    先让网站跑起来，确认自己会持续更新，再买域名。很多人第一天买了域名和服务器，第三天就不管了，钱白花。

    10

    改完怎么更新，怎么分享

    上线不是终点。改一个字、换一张图，都要再走一遍更新；而"谁能看到"这件事，也得你自己决定。

    更新：本机改了，网上不会自己变

    平台上的文件是你上传那一刻的复印件。你在电脑上改原件，复印件不会跟着变，必须重新传一次。

    1. 先在本地改好：保存文件，双击 index.html 确认没问题，再上传。别拿线上当试验田。
    2. 重新上传：Netlify 进站点的 Deploys 页面，找到 Need to update your site? 那个虚线框，把文件夹再拖一次；GitHub Pages 进仓库 → Add file → Upload files，传同名文件覆盖，再点 Commit changes。
    3. 强制刷新再看：电脑上按 Ctrl + F5；手机上关掉标签页重新打开，或者换个浏览器。

    为什么我改了，打开还是旧的

    九成是浏览器缓存。它把上次的 styles.css、图片存了起来，下次直接用，省流量也更快。所以先按 Ctrl + F5 强制刷新；还不行，就用一个从没打开过你网站的无痕窗口验证一次。

    生活类比

    餐厅换了新菜单，但老客人手里还拿着上次那张。缓存就是客人手里那张旧菜单：内容没错，只是过期了。强制刷新等于把旧菜单收走，换一张新的。

    谁能看到：公开还是私密

    这类免费托管默认是公开的：任何拿到链接的人都能打开，搜索引擎也可能把它收录。想让搜索引擎别收录，可以在 head 里加一行：

    index.html · 加在 head 里 
    <meta name="robots" content="noindex">

    注意：这只是"请搜索引擎别收录"，不等于加密，知道链接的人照样能看。真要密码保护，Netlify 和 Vercel 都有 Password protection，一般要付费。免费能做的，就是链接别到处发。

    "能打开"不等于"安全"

    公开链接等于公开内容。密码、身份证照片、公司内部文件、别人的联系方式，都不要放上去。已经传了又删不掉？把文件从文件夹里移走，重新上传一次。

    分享：发链接之前先自查

    • 直接发链接：微信、短信、邮件都行，对方点开就是你的网站。
    • 二维码：搜索引擎搜"网址转二维码"，生成后截图发人，线下贴出来也好用。
    • 发之前用无痕窗口打开一次：确认陌生人看到的内容和你一样，没有裂图、没有 404。
    11

    出错了怎么查

    网页出错很少给你一句明确的报错。学会按现象对照，比背语法有用得多。C 语言类比Console 像编译器给的错误行号，Network 像检查哪个头文件没找到。区别是网页的错误更安静，得你主动去看。

    现象最可能的原因怎么改
    打开是一片空白入口文件不叫 index.html，或内容没在 body 里检查文件名；把内容放进 body
    中文变成方块或乱码没声明 UTF-8head 里加 <meta charset="UTF-8">，文件另存为 UTF-8
    样式完全没生效CSS 路径写错，或选择器名字对不上打开开发者工具看 Network，确认 css 文件是否 404
    点了按钮没反应JS 报错，或脚本在元素之前执行按 F12 看 Console 的红色报错；脚本放 body 底部
    本地好看，上线裂图大小写不一致或用了绝对路径统一小写文件名，改成相对路径
    改了文件，网站没变化浏览器缓存Ctrl + F5 强制刷新，或换个浏览器试
    手机上看排版乱没写 viewporthead 里加 <meta name="viewport" content="width=device-width, initial-scale=1.0">
    最有用的一招

    在任何网页上按 F12，打开开发者工具。Console 面板看报错，Elements 面板看结构，Network 面板看哪个文件没加载成功。这一招能解决八成问题，比到处问人快。按了没反应笔记本键盘通常要按 Fn + F12；也可以右键页面空白处 → 检查，效果一样。

    常见问题

    一定要用 VS Code 吗？

    不一定。记事本也能改，只是没有颜色高亮，标签写漏了不容易看出来。VS Code 免费，装好之后能省很多找错的时间。

    上传后打开是空白，或者一堆文件名？

    基本是文件夹层级传错了。index.html 必须直接在网站根目录里，不能藏在 my-site 里面。回到第 8 节，重新拖一次里面的内容。

    需要买服务器吗？

    静态网站不需要。文件传上去就能用，免费的托管足够。等你要登录、留言、后台管理，才需要考虑服务器和数据库。

    能放视频吗？

    能，但视频文件很大，直接放会拖慢打开速度。更好的办法是传到视频网站，再用 <iframe> 或链接嵌进来。

    别人看到的和我不一样？

    先怀疑缓存。让对方按 Ctrl + F5，或者你自己用无痕窗口打开确认一次。第 10 节有完整流程。

    改坏了还能退回去吗？

    本地留一份备份最稳：整个文件夹复制一份，改名带日期。GitHub Pages 天然有提交历史，可以回滚到旧版本。

    网站会被别人搜到吗？

    公开的网站，搜索引擎迟早会收录。不想被收录，就在 head 里加 noindex，具体在第 10 节。

    顺手学会的电脑常识

    这件事为什么怎么做
    后缀名决定文件身份.html 是网页，.css 是样式，.js 是脚本，.txt 只是纯文本先在文件夹里打开「查看 → 文件扩展名」
    斜杠方向不一样网址和代码里用 /，Windows 本机路径用 \写网页路径一律用 /
    .zip 不是网页它是打包，只是把一堆文件装进一个盒子先右键解压，再改里面的文件
    中文名和空格容易出事服务器和网址对它们不友好，容易出现裂图、404文件名用英文小写，需要分隔就用短横线
    中文乱码是编码问题文件存的时候用的编码和浏览器读的不一致保存时选 UTF-8，页面里声明 charset
    改坏了要能退网页没有"自动保存历史"这回事整个文件夹复制一份，名字带上日期
    别背，用着用着就会了

    这些不是什么高深知识，是每天都会碰到的手边工具。快捷键先记住三五个，剩下的用一次记一次，比一次背二十个管用。

    最后一句

    网站不是一次做成的，是改出来的。

    你不需要先学会所有东西再动手。先把一个只有"你好，世界"的页面传上网，拿到那个链接，再去改颜色、加图片、加页面。每一次改动都比空想有用。

    接下来可以往哪走

    换成自己的内容

    改标题、换图片、写一段真实的介绍。网站里有了你的东西，才算你的。

    再学一点排版

    CSS 的 flex 和 grid 能做出两栏、卡片、居中的布局，够你用好一阵子。

    要存数据再往后

    登录、留言、后台管理，才需要服务器和数据库。现在完全不用碰。

    不想再手抄代码，就把示例文件下载下来，在能跑的基础上改，比从零开始快得多。想加内容、报错误，或者看看别人在做什么，去社区与反馈。

    记住这个顺序

    先能打开，再能看懂，然后能好看，最后才是能赚钱。绝大多数人卡在第一步，是因为想一次做到第四步。

    现在，去建那个文件夹吧。
